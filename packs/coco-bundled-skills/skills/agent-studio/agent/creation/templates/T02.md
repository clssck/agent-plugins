# T02 — Multi-Domain Analytics

Multiple business domains, each backed by its own semantic view. Requires orchestration routing so the agent picks the right tool per question.

## Tools

```yaml
tools:
  - tool_spec:
      type: cortex_analyst_text_to_sql
      name: <tool_a>
      description: "<What domain A data this queries and when to prefer it over other tools.>"
  - tool_spec:
      type: cortex_analyst_text_to_sql
      name: <tool_b>
      description: "<What domain B data this queries.>"
  - tool_spec:
      type: cortex_analyst_text_to_sql
      name: <tool_c>        # repeat per domain
      description: "<What domain C data this queries.>"

tool_resources:
  <tool_a>:
    execution_environment:
      type: warehouse
      warehouse: <WAREHOUSE>
    semantic_view: <DATABASE>.<SCHEMA>.<SV_DOMAIN_A>
  <tool_b>:
    execution_environment:
      type: warehouse
      warehouse: <WAREHOUSE>
    semantic_view: <DATABASE>.<SCHEMA>.<SV_DOMAIN_B>
  <tool_c>:
    execution_environment:
      type: warehouse
      warehouse: <WAREHOUSE>
    semantic_view: <DATABASE>.<SCHEMA>.<SV_DOMAIN_C>
```

## Instructions Starter

```yaml
instructions:
  response: |
    You are a <DOMAIN> analytics assistant for <ORGANIZATION>.
    <Persona-specific formatting rules — e.g., currency format, table vs. prose preference.>
  orchestration: |
    Route questions based on their topic:
    - <Topic A keywords, e.g., "purchase orders, vendor spend"> → use <tool_a>
    - <Topic B keywords, e.g., "inventory levels, stock">       → use <tool_b>
    - <Topic C keywords, e.g., "customer orders, pipeline">     → use <tool_c>
    If a question spans multiple topics, use the most relevant tool first.
```
