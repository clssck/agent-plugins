# AWS Defaults and Sources

Check an absent property against these defaults before reporting it. Rows were read from the cited primary documents on 2026-10-08. Re-verify before relying on anything not listed.

| Area | Current behavior | Control impact | Source |
|------|------------------|----------------|--------|
| S3 object encryption | SSE-S3 applies to every new object since 2023-01-05, and to existing buckets without default encryption. Cannot be disabled | Absent encryption config ≠ unencrypted. Objects uploaded earlier may be unencrypted | [Default encryption FAQ](https://docs.aws.amazon.com/AmazonS3/latest/userguide/default-encryption-faq.html) |
| S3 SSE-C | Since April 2026, new general purpose buckets reject SSE-C writes (HTTP 403), except in Middle East (Bahrain) and Middle East (UAE). Existing buckets were changed too unless the account already held SSE-C objects. Terraform: `blocked_encryption_types` on `aws_s3_bucket_server_side_encryption_configuration` (`SSE-C`, `NONE`) | `blocked_encryption_types = ["NONE"]` deliberately re-enables SSE-C: ask why. Absent block ≠ SSE-C allowed | [SSE-C default FAQ](https://docs.aws.amazon.com/AmazonS3/latest/userguide/default-s3-c-encryption-setting-faq.html); [Terraform resource](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket_server_side_encryption_configuration) |
| S3 ACLs | Object Ownership defaults to `BucketOwnerEnforced` on new buckets: ACLs are disabled and ignored, and requests that set ACLs fail | `public-read` ACL grants are inert unless `aws_s3_bucket_ownership_controls` sets `BucketOwnerPreferred` or `ObjectWriter`. Report the ownership setting with the ACL | [Object Ownership](https://docs.aws.amazon.com/AmazonS3/latest/userguide/about-object-ownership.html); [Terraform resource](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket_ownership_controls) |
| S3 public access | New buckets, access points, and objects don't allow public access. Block Public Access applies at organization, account, bucket, access point, most restrictive wins. Four settings: `BlockPublicAcls`, `IgnorePublicAcls`, `BlockPublicPolicy`, `RestrictPublicBuckets` | Public exposure needs a public ACL/policy AND no effective BPA. Terraform fields: `block_public_acls`, `ignore_public_acls`, `block_public_policy`, `restrict_public_buckets` | [Block Public Access](https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-control-block-public-access.html); [Terraform resource](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket_public_access_block) |
| SQS encryption | SSE is on by default for new queues (SSE-SQS) | Absent KMS key ≠ unencrypted; CMK is a policy choice | [Configure SSE for a queue](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-configure-sse-existing-queue.html); [SSE-SQS by default](https://aws.amazon.com/blogs/compute/announcing-server-side-encryption-with-amazon-simple-queue-service-managed-encryption-keys-sse-sqs-by-default) |
| Lambda function URL | New URLs need `lambda:InvokeFunctionUrl` and `lambda:InvokeFunction` since October 2025 | Judge effective Principal/Effect/Action/conditions, not a Sid | [Function URL access control](https://docs.aws.amazon.com/lambda/latest/dg/urls-auth.html) |
| Lambda permission (Terraform) | `aws_lambda_permission` has `function_url_auth_type` (with `lambda:InvokeFunctionUrl`) and `invoked_via_function_url` (with `lambda:InvokeFunction`) | Public NONE-auth URL: expect both statements; AWS recommends the `lambda:InvokedViaFunctionUrl` condition | [Function URL access control](https://docs.aws.amazon.com/lambda/latest/dg/urls-auth.html); [Terraform resource](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/lambda_permission) |
| Lambda networking | Runs in a Lambda-owned network unless a VPC config is set | Missing VPC config is not a finding by itself | [Lambda VPC](https://docs.aws.amazon.com/lambda/latest/dg/configuration-vpc.html) |
| API Gateway TLS | HTTP APIs and default endpoints enforce TLS | Only custom-domain TLS policy is checkable | [HTTP API ciphers](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-ciphers.html) |
| CloudFormation | `AWSTemplateFormatVersion` is optional | Detect templates by `Resources:` + `Type: AWS::` | [Template format version](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/format-version-structure.html) |
| CloudTrail | Organization trails are managed centrally | Local absence of a trail is not evidence | [Organization trail](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/creating-trail-organization.html) |
| CloudTrail Lake | Closed to new customers since 2026-05-31. Existing event data stores keep working (account-level stores do not ingest new organization member accounts). Trails, Insights, and Aggregated Events are unaffected | A repo adding `aws_cloudtrail_event_data_store` is an architecture question (CloudWatch is AWS's suggested alternative), not a vulnerability | [Lake availability change](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-lake-service-availability-change.html) |
| CloudTrail trail settings | `is_multi_region_trail` and `enable_log_file_validation` default to `false`; `kms_key_id` and `cloud_watch_logs_group_arn` have no default | A trail defined here MUST be judged on these four (LM-01). Absent = Confirmed gap on that trail | [Security Hub CloudTrail controls](https://docs.aws.amazon.com/securityhub/latest/userguide/cloudtrail-controls.html); [Terraform resource](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/cloudtrail) |
| RDS / Aurora encryption | `aws_db_instance` `storage_encrypted` and `aws_rds_cluster` `storage_encrypted` default to `false` (cluster default is `true` only for `engine_mode = "serverless"`) | Absent = unencrypted (EN-02). Unlike S3, no service default rescues it | [aws_db_instance](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/db_instance); [aws_rds_cluster](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/rds_cluster) |
| Redshift (provider v6) | `aws_redshift_cluster` `encrypted` defaults to `true` and `publicly_accessible` to `false` since provider 6.0. On provider 5.x they were not safe by default | Read the `required_providers` constraint and `.terraform.lock.hcl` before flagging absence. No v6 evidence → Needs confirmation | [v6 upgrade guide](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/guides/version-6-upgrade) |
| EC2 IMDS | Account/Region defaults (`aws_ec2_instance_metadata_defaults`, or an org declarative policy) apply to new launches. Per-instance `metadata_options` overrides. AMIs with `ImdsSupport: v2.0` launch with `HttpTokens=required`. Terraform `http_tokens` accepts `optional`/`required` | Explicit `http_tokens = "optional"` = Confirmed (NS-06). Absent = Needs confirmation | [Configure IMDS for new instances](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/configuring-IMDS-new-instances.html); [aws_instance](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/instance) |
| Aurora public access | `publicly_accessible` lives on instances, not the cluster | Inspect `aws_rds_cluster_instance` / `ClusterInstance` | [Terraform resource](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/rds_cluster_instance) |
| Terraform modules | `version` applies only to registry modules; Git pins via `?ref=`; local modules have no version | Per-source pin checks | [Module block](https://developer.hashicorp.com/terraform/language/block/module) |
| Terraform state locking | S3 backend `use_lockfile = true` is the supported lock. `dynamodb_table` is deprecated and will be removed in a future minor version | Missing lock = SM-03. A `dynamodb_table` alone is Informational (migrate), not a gap | [S3 backend](https://developer.hashicorp.com/terraform/language/backend/s3) |
| Terraform write-only arguments | Terraform 1.11+ and provider write-only arguments (`password_wo` + `password_wo_version` on `aws_db_instance`) keep the value out of plan and state. Plain `password` is stored in raw state. `manage_master_user_password = true` keeps RDS credentials in Secrets Manager | SM-02/SM-03 remediation targets | [Write-only arguments](https://developer.hashicorp.com/terraform/language/manage-sensitive-data/write-only); [aws_db_instance](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/db_instance) |
| Provider v6 `aws_instance.user_data` | No longer hashed: stored in clear text in state. Secrets in `user_data` are visible there | Raises SM-02 for any `user_data` carrying credentials; use `user_data_base64` only for encoding | [v6 upgrade guide](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/guides/version-6-upgrade) |
| Provider v6 `region` | Most resources accept a top-level `region`; on `aws_s3_bucket` and its data source the bucket region is `bucket_region` | Do not read a resource `region` as a data-residency violation without checking the provider alias and intended Regions | [Enhanced region support](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/guides/enhanced-region-support); [v6 upgrade guide](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/guides/version-6-upgrade) |
| Security group rules | `ingress`/`egress` blocks inside `aws_security_group` are discouraged. Provider docs recommend `aws_vpc_security_group_ingress_rule` / `_egress_rule` (`cidr_ipv4`, `cidr_ipv6`, `ip_protocol`, `from_port`) and warn against mixing both styles | NS-01 MUST inspect both styles. Mixed styles can make rules fight each other | [aws_security_group](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/security_group) |
| SST | Auth is set per route: `api.route(...)`. Bucket public access is `access: "public"` (default: none) | Match current SST props | [ApiGatewayV2](https://sst.dev/docs/component/aws/apigatewayv2); [Bucket](https://sst.dev/docs/component/aws/bucket) |
