# Send Notification

Sends a notification using [`SYSTEM$SEND_SNOWFLAKE_NOTIFICATION`](https://docs.snowflake.com/en/sql-reference/stored-procedures/system_send_snowflake_notification). Takes the content (generated by the `notification-content` skill) and a notification integration, wraps the content with the correct function, and executes the call.

This skill is authoritative for manual/custom dispatch using `SYSTEM$SEND_SNOWFLAKE_NOTIFICATION`.

**Reference:**
- [Using SYSTEM$SEND_SNOWFLAKE_NOTIFICATION to send notifications](https://docs.snowflake.com/en/user-guide/notifications/snowflake-notifications)
- [SYSTEM$SEND_SNOWFLAKE_NOTIFICATION stored procedure reference](https://docs.snowflake.com/en/sql-reference/stored-procedures/system_send_snowflake_notification)

## Workflow

### Step 1: Gather Input

**Required:**
```
1. Content (MANDATORY) - The user's message body, query_id, or text to send
2. Integration Name (MANDATORY) - Name of the notification integration to use
3. Integration Type (MANDATORY) - email, slack, teams, pagerduty, or default
```

**Optional (email only):**
```
4. Recipient(s) - Email address(es) to send to (overrides integration defaults)
5. Subject - Email subject line (overrides integration default)
```

**⚠️ STOP**: Confirm inputs before proceeding.

### Step 2: Verify Integration Exists

```sql
DESCRIBE NOTIFICATION INTEGRATION <integration_name>;
```

If the integration does not exist, **load** [../notification-integration/SKILL.md](../notification-integration/SKILL.md) to create it first.

### Step 3: Generate Formatted Content

**Always** load [../notification-content/SKILL.md](../notification-content/SKILL.md) to generate the content block. Pass it:
- The user's message body or query_id (from Step 1)
- The integration type (email, slack, teams, pagerduty, or default)
- Any optional arguments (header, footer, email subject)
- For webhook integrations: the `WEBHOOK_BODY_TEMPLATE` from the Step 2 `DESCRIBE` output

The notification-content skill produces a SQL content block with the correct wrapper function (out if `TEXT_HTML(string)`, `TEXT_PLAIN(string)`, `APPLICATION_JSON(string)`) for the integration type and adjusts it for the webhook body template if needed.

### Step 4: Send

Use the content block from Step 3 and call `SYSTEM$SEND_SNOWFLAKE_NOTIFICATION`. **Do NOT construct content wrappers yourself** — the notification-content skill already produced the correctly wrapped content.

**CRITICAL: Argument order is Content FIRST, Integration SECOND.**

#### Email

```sql
CALL SYSTEM$SEND_SNOWFLAKE_NOTIFICATION(
  <content_from_step_3>,
  '{"<integration_name>": {"subject": "<subject>", "toAddress": ["<email>"]}}'
);
```

**CRITICAL — Email integration properties are STRICTLY limited to:**

| Property | Type | Description |
|----------|------|-------------|
| `subject` | string | Email subject line |
| `toAddress` | array of strings | Recipient email address(es) |

**Do NOT add any other properties.** Properties like `message`, `body`, `recipient`, `content`, `from`, `html` etc. do NOT exist and will cause errors. The message body is passed entirely through the first argument (the content wrapper function).

**WARNING: Always include `toAddress` and `subject`.

**Note:** If the email integration was created without `ALLOWED_RECIPIENTS`, it can send to any verified email address in the account.

#### Webhook (Slack, Teams, PagerDuty)

```sql
CALL SYSTEM$SEND_SNOWFLAKE_NOTIFICATION(
  <content_from_step_3>,
  '{"<integration_name>": {}}'
);
```


## Stopping Points

- ✋ Step 1: After gathering inputs
- ✋ Step 2: If integration does not exist — create it first
- ✋ Step 3: After generating formatted content via notification-content skill
- ✋ After Step 4: Confirm delivery

## Troubleshooting

If a notification fails or does not arrive, check delivery status and errors through [NOTIFICATION_HISTORY](https://docs.snowflake.com/en/sql-reference/functions/notification_history):

```sql
SELECT * FROM TABLE(INFORMATION_SCHEMA.NOTIFICATION_HISTORY())
ORDER BY CREATED DESC
LIMIT 10;
```

**Input parameters** (all optional):

| Parameter | Type | Description |
|-----------|------|-------------|
| `INTEGRATION_NAME` | VARCHAR | Filter by integration name |
| `START_TIME` | TIMESTAMP_LTZ | Start of time range |
| `END_TIME` | TIMESTAMP_LTZ | End of time range |

**Output columns:**

| Column | Type | Description |
|--------|------|-------------|
| `CREATED` | TIMESTAMP_LTZ | When the notification was created |
| `PROCESSED` | TIMESTAMP_LTZ | When the last send attempt was made |
| `MESSAGE_SOURCE` | VARCHAR | Source type: `BUDGET`, `TASK`, `SNOWPIPE`, `STORED_PROCEDURE` |
| `INTEGRATION_NAME` | VARCHAR | Name of the integration used |
| `STATUS` | VARCHAR | `QUEUED`, `SUCCESS`, `RETRIABLE_FAILURE`, `FAILURE` |
| `ERROR_MESSAGE` | VARCHAR | Details if the notification failed |
| `ID` | VARCHAR | Unique request ID (same across retries) |
| `ATTEMPT` | INTEGER | Attempt number |
| `MESSAGE_SOURCE_INFO` | OBJECT | Source-specific metadata (e.g., `query_id` for stored procedure calls) |

## Output

- Notification sent via `SYSTEM$SEND_SNOWFLAKE_NOTIFICATION`
- Delivery status can be verified via [NOTIFICATION_HISTORY](https://docs.snowflake.com/en/sql-reference/functions/notification_history)
