# Script CLI Reference

All scripts are in the `scripts/` directory. They require `psycopg2-binary` or `pg8000`.

Most database-connecting scripts use the shared `pg_common.py` argument layer.
For chat-safe workflows, prefer `--source-service` / `--target-service` so
host/user/SSL settings come from `~/.pg_service.conf` and passwords stay in
`~/.pgpass`. The host/db/user examples below remain supported for trusted
shells and stay close to the upstream operator runbooks.

## Common Source Flags (via pg_common.py)

All scripts that connect to the source accept these flags:

| Flag | Alias | Env Variable | Default | Description |
|------|-------|-------------|---------|-------------|
| `--source-service` | | `SOURCE_PG_SERVICE` | | Load host/hostaddr/port/dbname/user/sslrootcert from `~/.pg_service.conf[NAME]`; password from `~/.pgpass` (preferred) |
| `--host` | `-H`, `--source-host` | `SOURCE_PGHOST` | | Source PostgreSQL host |
| `--hostaddr` | | `SOURCE_PGHOSTADDR` | | Optional source IP for libpq DNS-bypass flows; keep `--host` for TLS/pgpass identity |
| `--port` | `-p`, `--source-port` | `SOURCE_PGPORT` | `5432` | Source port |
| `--dbname` | `-d`, `--source-dbname` | `SOURCE_PGDATABASE` | | Source database |
| `--user` | `-U`, `--source-user` | `SOURCE_PGUSER` | | Source username |
| `--password` | `-W` | `PGPASSWORD`, `SOURCE_PGPASSWORD` | | Source password (trusted-shell fallback; prefer `--source-service`) |
| `--sslmode` | | | | `disable`, `require`, `verify-ca`, `verify-full` |

## Common Target Flags

Scripts that connect to the target accept:

| Flag | Env Variable | Default | Description |
|------|-------------|---------|-------------|
| `--target-service` | `TARGET_PG_SERVICE` | | Load target host/hostaddr/port/dbname/user/sslrootcert from `~/.pg_service.conf[NAME]`; password from `~/.pgpass` (preferred) |
| `--target-host` | `TARGET_PGHOST` | | Target Snowflake Postgres host |
| `--target-hostaddr` | `TARGET_PGHOSTADDR` | | Optional target IP for libpq DNS-bypass flows; keep `--target-host` for TLS/pgpass identity |
| `--target-port` | `TARGET_PGPORT` | `5432` | Target port |
| `--target-dbname` | `TARGET_PGDATABASE` | | Target database |
| `--target-user` | `TARGET_PGUSER` | | Target username |
| `--target-password` | `TARGET_PGPASSWORD` | | Target password (trusted-shell fallback; prefer `--target-service`) |
| `--target-sslmode` | | | Target SSL mode |

When a service name is present, scripts resolve any missing connection fields
from the named profile before validating required args. Register profiles with
`python <SKILL_DIR>/scripts/shared/pg_common.py --add-source-service NAME ...`
and the matching target command.

## run_assessment.py

Full migration assessment with HTML report. Keeps the upstream self-contained
assessment logic, but uses the shared source-connection flags from
`pg_common.py`, including `--source-service`.

**Connects to:** Source only

**Flags:**

| Flag | Description |
|------|-------------|
| `--source-service NAME` | Load source host/port/dbname/user/sslrootcert from `~/.pg_service.conf`; password from `~/.pgpass` |
| `--host`, `-H` | Source host (or `SOURCE_PGHOST`) |
| `--port`, `-p` | Source port (default: 5432) |
| `--dbname`, `-d` | Database name |
| `--user`, `-U` | Username |
| `--password`, `-W` | Password fallback (prefer `--source-service`) |
| `--sslmode` | SSL mode |
| `--html FILE` | Generate HTML report (default: `migration_assessment_report.html`) |
| `--json FILE` | Save JSON assessment data |
| `--schemas LIST` | Comma-separated schemas to assess (default: all) |
| `--open FILE` | Open an existing HTML report in the default browser and exit |
| `--no-open` | Do not auto-open the generated HTML report |
| `--quiet`, `-q` | Suppress progress output |

**Examples:**
```bash
# Preferred, chat-safe workflow:
uv run --project <SKILL_DIR> python <SKILL_DIR>/migrate/scripts/run_assessment.py \
    --source-service prod_source \
    --html migration_assessment_report.html \
    --json assessment_data.json

# Legacy trusted-shell workflow:
python scripts/run_assessment.py \
    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER \
    --html migration_assessment_report.html --json assessment_data.json

python scripts/run_assessment.py \
    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER \
    --schemas public,analytics

# Re-open an existing report without re-running the assessment:
python scripts/run_assessment.py --open migration_assessment_report.html
```

**Output:** Text summary to stdout, HTML report (generated by default and
auto-opened unless `--no-open`), optional JSON.

## test_connectivity.py

Test DNS, TCP, auth, replication settings, write access, and target→source network path.

**Connects to:** Source and Target

**Additional flags:**

| Flag | Description |
|------|-------------|
| `--json FILE` | Save results as JSON |

**Examples:**
```bash

    --source-service prod_source --target-service sf_target

    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER \
```

## validate_migration.py

Compare source and target databases: row counts, checksums, aggregates. Handles materialized views separately (always uses exact counts for matviews).

**Connects to:** Source and Target

**Additional flags:**

| Flag | Description |
|------|-------------|
| `--mode` | `quick` (default: pg_stat counts), `exact` (SELECT count(*) on mismatches), `full` (+ checksums + aggregates) |
| `--html FILE` | Generate HTML validation report |
| `--json FILE` | Save JSON results |
| `--schemas LIST` | Comma-separated schemas to validate (default: all) |

**Examples:**
```bash
python scripts/validate_migration.py \
    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER \
    --target-host $TARGET_PGHOST --target-dbname $TARGET_PGDATABASE --target-user $TARGET_PGUSER

python scripts/validate_migration.py \
    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER \
    --target-host $TARGET_PGHOST --target-dbname $TARGET_PGDATABASE --target-user $TARGET_PGUSER \
    --mode full --html validation.html --schemas public,analytics
```

**Output:** Text comparison report. Exit 0 if pass, 1 if mismatches found.

## generate_hybrid_plan.py

Generate a hybrid migration plan for databases with mixed replicable/non-replicable objects. Properly handles partitioned tables and inherited table children.

**Connects to:** Source only

**Additional flags:**

| Flag | Description |
|------|-------------|
| `--target-host` | Target host (for plan generation, env: `TARGET_PGHOST`) |
| `--output`, `-o` | Output base filename (default: `migration_plan`) |
| `--format`, `-f` | `all` (default), `html`, `json`, `sh` |
| `--schemas LIST` | Comma-separated schemas to include (default: all) |
| `--dump-timing` | `now` (default) or `cutover`. Controls when non-replicable tables are dumped. `now` = dump during migration after replication starts. `cutover` = defer dump to cutover phase alongside sequence sync. |

**Examples:**
```bash
python scripts/generate_hybrid_plan.py \
    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER \
    --target-host $TARGET_PGHOST -o migration_plan

python scripts/generate_hybrid_plan.py \
    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER \
    --target-host $TARGET_PGHOST --schemas public,analytics -f html

python scripts/generate_hybrid_plan.py \
    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER \
    --target-host $TARGET_PGHOST --dump-timing cutover -o migration_plan
```

**Output:** HTML report, JSON plan, and/or shell script depending on `--format`.

## prepare_target.py

Pre-restore target preparation and safety checks. Has 4 subcommands.

**Connects to:** Target (and Source for `extensions` subcommand)

### `preflight-check` (MANDATORY before any migration)

Verifies target schemas don't already contain objects.

| Flag | Description |
|------|-------------|
| `--schemas` | **Required.** Comma-separated list of schemas being migrated |
| `--i-understand-the-risks` | Bypass safety check (acknowledges target schemas may contain objects that will be overwritten or merged). Long form is intentional — never type this in CI. |
| + target flags | Required |

```bash
python scripts/prepare_target.py preflight-check \
    --target-host $TARGET_PGHOST --target-dbname $TARGET_PGDATABASE --target-user $TARGET_PGUSER \
    --schemas public,analytics,reporting
```

### `extensions`

Creates source extensions on target.

| Flag | Description |
|------|-------------|
| `--dry-run` | Show SQL without executing |
| + source and target flags | Required |

```bash
python scripts/prepare_target.py extensions \
    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER \
    --target-host $TARGET_PGHOST --target-dbname $TARGET_PGDATABASE --target-user $TARGET_PGUSER

python scripts/prepare_target.py extensions ... --dry-run
```

### `check-data`

Check if target schemas already contain data.

| Flag | Description |
|------|-------------|
| `--schemas` | Optional. Comma-separated schemas to check |
| + target flags | Required |

```bash
python scripts/prepare_target.py check-data \
    --target-host $TARGET_PGHOST --target-dbname $TARGET_PGDATABASE --target-user $TARGET_PGUSER \
    --schemas public,analytics
```

### `clean-schemas`

DROP and recreate target schemas.

| Flag | Description |
|------|-------------|
| `--schemas` | **Required.** Comma-separated schemas to drop/recreate |
| `--confirm` | Actually execute (dry run without this flag) |
| + target flags | Required |

```bash
python scripts/prepare_target.py clean-schemas \
    --target-host $TARGET_PGHOST --target-dbname $TARGET_PGDATABASE --target-user $TARGET_PGUSER \
    --schemas analytics,reporting --confirm
```

## post_migration_cleanup.py

Tear down replication artifacts after a successful migration.

**Connects to:** Source and/or Target

| Flag | Description |
|------|-------------|
| `--dry-run` | Show what would be cleaned up without executing |
| `--source-only` | Only clean up source artifacts (publications, replication slots) |
| `--target-only` | Only clean up target artifacts (subscriptions, test objects) |
| `--subscription-name NAME` | Optional target subscription name to drop. Repeat for multiple names; useful when subscriptions are disabled or custom-named. |
| + source flags | Required unless `--target-only` |
| + target flags | Required unless `--source-only` |

```bash
python scripts/post_migration_cleanup.py \
    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER \
    --target-host $TARGET_PGHOST --target-dbname $TARGET_PGDATABASE --target-user $TARGET_PGUSER \
    --dry-run

python scripts/post_migration_cleanup.py \
    --target-host $TARGET_PGHOST --target-dbname $TARGET_PGDATABASE --target-user $TARGET_PGUSER \
    --target-only --subscription-name migrate_from_source

python scripts/post_migration_cleanup.py \
    -H $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER --source-only
```

**Verification after cleanup** (adjust the names if you used custom subscription / slot names):

```sql
-- On SOURCE: publication removed
SELECT pubname
FROM pg_publication
WHERE pubname = 'snowflake_migration';

-- On SOURCE: slots removed
SELECT slot_name
FROM pg_replication_slots
WHERE slot_name IN ('migration_sub', 'migrate_from_source', 'reverse_sub');

-- On TARGET: no enabled workers for the migration subscriptions
SELECT subname, pid
FROM pg_stat_subscription
WHERE subname IN ('migration_sub', 'migrate_from_source', 'reverse_sub');

-- Optional on TARGET, if pg_subscription is readable in your environment:
SELECT subname
FROM pg_subscription
WHERE subname IN ('migration_sub', 'migrate_from_source', 'reverse_sub');
```

Expect zero rows from each query after cleanup.

## filter_vendor_dump.py

Filter vendor-specific commands from pg_dump output. Supports Crunchy Bridge, AWS RDS, Azure, Google Cloud SQL, and Neon platform roles.

**No database connection required.**

| Flag | Description |
|------|-------------|
| `-v`, `--verbose` | Show what was filtered (to stderr) |
| `-s`, `--stats` | Show filter statistics at end |
| `-h`, `--help` | Show help |
| `[input_file]` | Optional input file (otherwise reads stdin) |

```bash
pg_dump -h $SOURCE_PGHOST -d $SOURCE_PGDATABASE -U $SOURCE_PGUSER | \
    python ./scripts/filter_vendor_dump.py > clean_dump.sql

python ./scripts/filter_vendor_dump.py --stats dump.sql > clean_dump.sql
```

**Filters:** Crunchy `\restrict`/`\unrestrict`, RDS `rds.*` functions/roles, Azure `azure.*`, GCP `cloudsql*`, Neon `cloud_admin` / `neon_service` / `neon_superuser`, role attributes (`SUPERUSER`, `REPLICATION`, `BYPASSRLS`).
