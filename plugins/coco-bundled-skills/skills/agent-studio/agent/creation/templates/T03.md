# T03 — Hybrid RAG + SQL

One semantic view for structured data questions plus one Cortex Search service for document/policy retrieval. Most common high-engagement pattern in production.

## Tools

```yaml
tools:
  - tool_spec:
      type: cortex_analyst_text_to_sql
      name: <DataTool>
      description: "<What structured data this covers and when to call it vs. the search tool.>"
  - tool_spec:
      type: cortex_search
      name: <SearchTool>
      description: "<What documents this searches and what questions it answers.>"

tool_resources:
  <DataTool>:
    execution_environment:
      type: warehouse
      warehouse: <WAREHOUSE>
    semantic_view: <DATABASE>.<SCHEMA>.<SEMANTIC_VIEW>
  <SearchTool>:
    search_service: <DATABASE>.<SCHEMA>.<CORTEX_SEARCH_SERVICE>
    id_column: <ID_COLUMN>
    title_column: <TITLE_COLUMN>
    max_results: 5
```

## Instructions Starter

```yaml
instructions:
  response: |
    You are a <DOMAIN> assistant for <ORGANIZATION>.
    For data questions, present results in tables with clear column headers.
    For document search results, cite the source document and relevant excerpt.
  orchestration: |
    Route questions based on their nature:
    - Structured data questions (counts, totals, trends, comparisons) → use <DataTool>
    - Document / text search (policies, contracts, runbooks, FAQs)   → use <SearchTool>
    - When a question requires both, call <DataTool> first then <SearchTool>.
```
