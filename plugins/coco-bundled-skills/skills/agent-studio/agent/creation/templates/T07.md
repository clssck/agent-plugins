# T07 — Integration/Action

Action-only agent — no data Q&A. Use for operational and admin workflows that trigger actions without needing to query structured data first.

Two action variants — pick the one that matches your setup:
- **Procedure/UDF** — actions are Snowflake stored procedures or UDFs already in your account
- **MCP/Integration** — actions go through an external system (Jira, Salesforce, Slack, etc.) or a complex SPCS-hosted service, accessed via a pre-existing MCP Server object

---

## Variant A: Procedure/UDF Actions

Before writing this spec: confirm the user can describe the exact input parameters for each action tool. Since this agent executes operations directly, the instructions must tell it to confirm before anything destructive (DROP, DELETE, DISABLE, PURGE).

```yaml
tools:
  - tool_spec:
      type: generic
      name: <action_tool_1>
      description: "<What this tool does and when to invoke it.>"
      input_schema:
        type: object
        properties:
          <param_1>:
            type: string
            description: "<What this parameter controls>"
          <param_2>:
            type: string
            description: "<Valid values — e.g., XSMALL | SMALL | MEDIUM | LARGE>"
        required:
          - <param_1>
          - <param_2>
  - tool_spec:
      type: generic
      name: <action_tool_2>       # no-parameter tool, e.g. list / summary
      description: "<What this tool returns. No inputs needed.>"
      input_schema:
        type: object
        properties: {}

tool_resources:
  <action_tool_1>:
    type: procedure
    identifier: <DATABASE>.<SCHEMA>.<SP_NAME>
    execution_environment:
      type: warehouse
      warehouse: <WAREHOUSE>
  <action_tool_2>:
    type: procedure
    identifier: <DATABASE>.<SCHEMA>.<SP_NAME>
    execution_environment:
      type: warehouse
      warehouse: <WAREHOUSE>
```

---

## Variant B: MCP/Integration Actions

The MCP Server object (`<DATABASE>.<SCHEMA>.<MCP_SERVER>`) must already exist in Snowflake before writing this spec. The agent discovers all tools the MCP server exposes automatically.

```yaml
mcp_servers:
  - server_spec:
      name: <DATABASE>.<SCHEMA>.<MCP_SERVER>
```

> To also include document search alongside MCP actions, add a `cortex_search` tool + its `tool_resources` entry (see T06 for the search tool shape).

## Instructions Starter

```yaml
instructions:
  response: |
    You are a <DOMAIN> administration assistant for <ORGANIZATION>.
    Provide concise, actionable responses.
    Always ask for confirmation before executing destructive operations (DROP, DELETE, DISABLE, PURGE).
  orchestration: |
    Route requests as follows:
    - <Resource type A> management (create, list) → use <action_tool_1>, <action_tool_2>
    - <Resource type B> operations (configure)    → use <other_tool>
    Always ask for confirmation before any destructive operation.
```
