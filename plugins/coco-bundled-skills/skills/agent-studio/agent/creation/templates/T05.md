# T05 — Analyst + Action

One semantic view for data queries plus an action capability. Use when the agent needs to both answer questions from data AND trigger an action.

Two action variants — pick the one that matches your setup:
- **Procedure/UDF** — action is a Snowflake stored procedure or UDF already in your account
- **MCP/Integration** — action is an external system (Jira, Salesforce, Slack, etc.) or a complex SPCS-hosted service, accessed via a pre-existing MCP Server object

---

## Variant A: Analyst + Procedure/UDF Action

Before writing this spec: confirm the user can describe the exact input parameters — name, type, and what each controls. Without that, the `input_schema` cannot be filled in and the tool call will fail at runtime.

```yaml
tools:
  - tool_spec:
      type: cortex_analyst_text_to_sql
      name: <DataTool>
      description: "<What structured data this queries — tables, metrics, filters.>"
  - tool_spec:
      type: generic
      name: <ActionTool>
      description: "<What this tool computes or triggers and when to invoke it.>"
      input_schema:
        type: object
        properties:
          <param_1>:
            type: string
            description: "<What this parameter controls>"
          <param_2>:
            type: number
            description: "<What this parameter controls>"
        required:
          - <param_1>
          - <param_2>

tool_resources:
  <DataTool>:
    execution_environment:
      type: warehouse
      warehouse: <WAREHOUSE>
    semantic_view: <DATABASE>.<SCHEMA>.<SEMANTIC_VIEW>

  # Stored procedure variant:
  <ActionTool>:
    type: procedure
    identifier: <DATABASE>.<SCHEMA>.<SP_NAME>
    execution_environment:
      type: warehouse
      warehouse: <WAREHOUSE>

  # UDF / function variant (use instead of procedure above):
  # <ActionTool>:
  #   type: function
  #   name: <DATABASE>.<SCHEMA>.<FN_NAME>!<METHOD>
  #   warehouse: <WAREHOUSE>
```

## Variant B: Analyst + MCP/Integration Action

The MCP Server object (`<DATABASE>.<SCHEMA>.<MCP_SERVER>`) must already exist in Snowflake before writing this spec. The agent discovers the MCP server's tools automatically — no `input_schema` needed in the agent spec.

```yaml
tools:
  - tool_spec:
      type: cortex_analyst_text_to_sql
      name: <DataTool>
      description: "<What structured data this queries — tables, metrics, filters.>"

tool_resources:
  <DataTool>:
    execution_environment:
      type: warehouse
      warehouse: <WAREHOUSE>
    semantic_view: <DATABASE>.<SCHEMA>.<SEMANTIC_VIEW>

mcp_servers:
  - server_spec:
      name: <DATABASE>.<SCHEMA>.<MCP_SERVER>
```

## Instructions Starter

```yaml
instructions:
  response: |
    You are a <DOMAIN> analytics assistant for <ORGANIZATION>.
    You answer data questions about <TOPIC> and can also <what the action/integration does>.
    For actions, always confirm the result with the user.
  orchestration: |
    Use <DataTool> for questions about existing data: counts, averages, trends,
    comparisons, and lookups across <DATA_DOMAIN>.
    Use the action capability when the user asks to trigger a process, run a prediction,
    create a record, or interact with an external system — not for querying existing data.
```
